# 使用指南

## 1. 选择一份示例

| 文件 | 用途 | 是否需要图片 |
|---|---|---|
| [text-create.json](../examples/text-create.json) | 从想法创作扩写 | 否 |
| [text-refine.json](../examples/text-refine.json) | 忠实润色已有描述 | 否 |
| [reference-describe.json](../examples/reference-describe.json) | 忠实反推参考图 | 是 |
| [reference-create.json](../examples/reference-create.json) | 参考图＋用户新想法 | 是 |
| [image-edit.json](../examples/image-edit.json) | 生成图片编辑指令 | 是 |
| [reference-precise.json](../examples/reference-precise.json) | 三阶段参考图反推 | 是 |
| [text-openai.json](../examples/text-openai.json) | 官方 OpenAI 文本任务配置示例 | 否 |

将 JSON 文件拖入 ComfyUI。ZIP 安装包应先解压安装，不能作为工作流导入。示例只包含提示词处理流程，实际生图节点使用你自己的工作流。

## 2. 配置 LLM 服务

双击左侧配置子图，其中包含“LLM 服务配置”“模板预设编辑器”“任务配置”三个节点。

### 本地或兼容服务

| 字段 | 填写方式 |
|---|---|
| provider | `local` |
| base_url | 服务基础地址，例如 `http://127.0.0.1:8000/v1` |
| model | 服务实际提供的模型 ID；不要留空 |
| api_type | `auto` 默认选择 Chat Completions |
| api_key_env | 无需认证的本地服务可留空；有认证时填后端环境变量名 |
| max_output_tokens | 默认 4096，输出截断时可试 8192；开启思考时可根据上下文和耗时需求增加 |
| timeout_seconds | 单次请求超时，默认 300 秒 |
| image_max_side | 发送给 LLM 的图像最长边，默认 1536；不改变下游出图尺寸 |

`base_url` 不包含 `/chat/completions` 或 `/responses`。`local` 表示使用自定义接口，不代表请求一定在同一台电脑上。Docker 中的 localhost 是容器自身，地址必须从 ComfyUI 后端可访问。

`api_key_env` 示例值为 `MY_LLM_API_KEY`，实际密钥应设置在运行 ComfyUI 的环境中。不要将密钥本身粘贴到该字段。留空时，本地接口可读取可选的 `SAMUEL_ENHANCER_API_KEY`。

### 官方 OpenAI

选择 `provider=openai`，基础地址由程序固定，`api_type=auto` 使用 Responses。填写支持所需输入和结构化输出的模型 ID，并在 ComfyUI 后端设置 `OPENAI_API_KEY`。自定义变量名可填入 `api_key_env`。

文字和参考图片会发送到选定服务，服务的配额、计费和数据处理规则由提供方决定。本插件不附带账户、API Key 或模型权重。

### 思考开关

部分 llama.cpp / Qwen 模板支持：

```json
{"chat_template_kwargs":{"enable_thinking":false}}
```

关闭思考可以减少生成开销；需要复杂约束推理时可试 `true`，并配合更大的输出预算，例如 16384。该参数依赖服务和模板，不适用于所有接口；官方 OpenAI 不应直接套用这一设置。

提高预算不强制生成满，也不放宽最终正文篇幅。输入、图像、思考和输出须能容纳于服务实际开放的上下文。精确模式有三次调用，每次都有独立预算和超时。

## 3. 选择模板和任务

- 文本创作、参考图反推使用 `generation` 模板，输出六节完整目标画面。
- 图片编辑使用 `editing` 模板，输出 Edit Goal、Preserve、Modify、Result 四节指令。

模板正文和任务适配规则均可编辑，随工作流保存。切换模板会分别保存并恢复各自手稿。“恢复当前预设默认内容”会覆盖当前预设的手稿，不影响另一份预设。

文本任务的“创作扩写”允许补充未指定的设计，“忠实润色”保留已有设计。参考图任务的“忠实反推”描述实际可见内容，“参考图创作”结合图片与用户的新要求设计新画面。模式由下拉框选择，不靠输入长短自动判断。

## 4. 输入创作内容

`user_text` 连接文本输入节点。可选的 `must_keep` 突出必须保持的特征；同一要求不必在两个位置重复。

例如：

```text
雨夜的古城茶馆，两位成年剑客隔桌对坐。
左侧人物右手持茶杯、左手平放桌面；右侧人物双手放在桌上。
写实电影摄影，用中文输出。
```

参考图忠实反推可以不填用户文本，也可填写观察重点；参考图创作和图片编辑必须提供新想法或明确修改要求。图片输入只支持单张 IMAGE，不接收 MASK 或多图批次。

## 5. 篇幅和生成方式

| 档位 | 中文正文硬上限 | 英文正文硬上限 |
|---|---:|---:|
| 详细 | 1500 汉字 | 800 词 |
| 简单 | 750 汉字 | 400 词 |

不设最低长度，不为凑字数补写。生成指导预留 15% 计数余量，最终仍按硬上限校验。标题不计入正文长度，汉字统计不含标点；中英文混合时按所选正文语言对应的计数项检查。

- 标准：一次调用，适合先确认服务与格式。
- 精确：观察/约束、生成、复核三次调用，适合约束较多的场景。图片任务每次请求都带同一参考图。

精确模式表示执行了模型复核，不能保证没有语义错误，也不能验证下游图片的人体结构。发生格式、截断、超限或冲突错误时停止，不把错误文字传给下游，不回退未经复核的草稿，不额外增加修复调用。

## 6. 预览和手改

“文本预览”只读显示输入。“提示词编辑与预览”支持：

1. 直接使用：输出生成原稿。
2. 完整编辑：先运行生成，点击“载入原稿到编辑框／恢复原稿”，修改正文，再执行下游。
3. 追加补充：将补充文本接到 `addition`，在原稿后拼接；不会调用模型自动消除冲突。

新上游结果不会覆盖手动正文。修改后需要再次执行才能更新输出。若需永久固定一份文本，可复制到独立文本输入节点并断开 LLM 分支。

## 7. 接到生图或编辑工作流

```text
配置子图 ───┐
用户文本 ───┼→ Samuel-Enhancer 任务节点 → 编辑/预览 → 文本编码 → 你的生图工作流
保持项 ─────┤                      └→ info 运行信息
参考图片 ───┘
```

`prompt` 是 STRING，应连接到接受字符串的文本编码器，不能直接接 KSampler 的 CONDITIONING。负面词按下游模型和采样流程处理，插件不生成默认负面词。

实际分辨率由 Latent、图像缩放或编辑节点决定。配置中的可选 target_width/target_height 只指导构图，两者须同时提供。忠实反推保留原图构图，编辑任务除非明确要求裁切/扩图，否则保留原图画幅。

## 8. 缓存与重新扩写

`refresh_id` 是重新扩写编号，不是图像或 LLM 的 seed。需要新一轮扩写时改变它；只修改下游生图 seed 不会主动刷新 LLM。重启或清缓存后，上游可能重新执行。

0.3.x 旧工作流可在浏览器加载时自动迁移到新节点名。保存迁移后的工作流；API 用户应重新导出 API 格式。0.1/0.2 的旧单体节点需换用当前示例。
